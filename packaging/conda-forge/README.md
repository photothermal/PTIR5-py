# conda-forge packaging

Recipe scaffolding for submitting `ptir5` to [conda-forge](https://conda-forge.org/).

## Submitting a new version

1. Publish the matching release to PyPI:
   ```bash
   python -m build
   twine upload dist/*
   ```
2. Compute the sdist hash:
   ```bash
   curl -sL https://pypi.io/packages/source/p/ptir5/ptir5-<version>.tar.gz | sha256sum
   ```
3. Update `version` and `sha256` in `meta.yaml`.
4. Fill in your GitHub handle under `recipe-maintainers`.

## First submission

- Fork https://github.com/conda-forge/staged-recipes.
- Copy `meta.yaml` to `recipes/ptir5/meta.yaml` in the fork.
- Open a PR titled `Add ptir5`.
- Address bot lint output and any reviewer feedback.
- On merge, `conda-forge/ptir5-feedstock` is created automatically.

## After the feedstock exists

Do not edit this file for routine releases. The `regro-cf-autotick-bot` opens
PRs on the feedstock when new PyPI versions ship. Review, ensure CI is green,
and merge. Only update this in-tree copy when the recipe shape itself changes
(new dependency, Python floor bump, etc.) so it stays a useful reference.
