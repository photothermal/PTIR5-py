## Review Focus

1. A tree `NODES` row names a GUID that has no `/TREE/{guid}` group, as an interrupted attach/detach can leave (b06deb4). The tree should still load and omit that row (spec §14.5). Test: Task 6.
2. A fixed-length ASCII string attribute holds non-UTF-8 bytes, as pre-PS-2604 files can (cp1252 `µ`). Metadata should still load, with the bad bytes replaced by U+FFFD. Test: Task 6.
3. `ComponentCompletion` holds a value other than 0 or 1. That component should read as incomplete, never complete: spec §7.4.1 says fail closed. Test: Task 3.
4. A band image's own `NormalizeMode` is not supported by its parent cube type, which a copy across cube types produces. The effective mode should be `Off` with the image's own reference, never the cube's setting (spec §13.4). Test: Task 4.
5. Derived output is written from a noise-frame-corrected O-PTIR stack. The result should carry no noise-frame link, so PTIR Studio cannot add the source noise frame onto derived values. Test: Task 7.

### Task 2: `FLPTIRImage` dual-format reading

The SDK reads `FLPTIRImage` from a rank-2 `(H, W)` dataset (float32 `Gray32Float`, uint16 `Gray16` or uint8 `Gray8`; dtype decides, `FLPTIRImage.cs:824-844`) or from the legacy rank-3 `(H, W, 4)` uint8 layout, which holds float32 bytes. Its `ReadFloat` returns float32 for every layout. This task applies to images the approach PR #6 used for stacks.

- Modify: `src/ptir5/enums.py` (`TYPE_TO_SHAPE[FLPTIRImage]` becomes `FLOAT_IMAGE_2D`, with the same "chosen at build time" comment the stack entry has)

- Modify: `docs/data_types.md`, `docs/api_reference.md`, `CHANGELOG.md`

**Interfaces:**
- Consumes: the existing `_reinterpret_legacy_flptir_bytes(raw, hdf5_path)`; `write_ptir` (Task 1).
- Produces:
  - `class FLPTIRImage`: public marker mixin, replacing today's `FLPTIRImage(ByteImage2D)`. It declares `is_legacy: bool`, `data_float32 -> np.ndarray[(H, W), float32]` and `pixel_format -> PixelFormat | str`.
  - `_LegacyFLPTIRImage(FLPTIRImage, ByteImage2D)`: rank 3, `data_shape = BYTE_IMAGE_2D`; `data_float32` reinterprets the bytes and validates them at read time.
  - `_Rank2FLPTIRImage(FLPTIRImage, FloatImage2D)`: rank 2, `data_shape = FLOAT_IMAGE_2D`; `data_float32` is `data.astype(np.float32)`.
  - `_resolve_pixel_format(metadata: MetadataView) -> PixelFormat | str`: the lookup `ByteImage2D`, `ImageStack3D` and `FLPTIRImage` all use now. Extract it; don't duplicate it.
  - Build rules, all raising `InvalidMeasurementError`:
    - `DATA` missing: error.
    - rank 3: legacy.
    - rank 2 with dtype in {float32, uint16, uint8}: rank-2 class.
    - rank 2 with any other dtype: error.
    - any other rank: error.

  Put these rules in a helper, `_flptir_image_class(reader, hdf5_path) -> tuple[type[Measurement], DataShape]`, called from `build_measurement`.

### Task 4: Normalization settings

The `ptir5` objects report the *setting* the SDK would render with; they do not normalize data. The rules are copied from `HyperspectralArrayData.cs:61-167`, `GeneratedImage.cs:80-136` and spec §13.4.

**Files:**
- Modify: `src/ptir5/enums.py` (add `NormalizeMode`)
- Modify: `src/ptir5/models.py` (add `NormalizeSpec`; members on `HyperspectralCube`, `TimeDomainCube`, `GeneratedImage`)
- Modify: `src/ptir5/__init__.py` (export `NormalizeMode`, `NormalizeSpec`)
- Create: `tests/test_normalization.py`
- Modify: `docs/data_types.md`, `docs/api_reference.md`, `CHANGELOG.md`

**Interfaces:**
- Consumes: `HyperspectralCube`, `TimeDomainCube` and `write_ptir` (Task 1).
- Produces:
  - `class NormalizeMode(StrEnum)`: `Off`, `Peak`, `Wavenumber`, `Time`, `Offset`; each value is its name.
  - `@dataclass(frozen=True, slots=True) class NormalizeSpec`, with fields `mode: NormalizeMode` and `reference: float | None`.
  - `_parse_normalize_mode(raw: object) -> NormalizeMode | None`: case-insensitive match against member names for `str` input; `None` for anything else.
  - `HyperspectralCube.supported_normalize_modes: ClassVar[frozenset[NormalizeMode]] = {Off, Peak, Wavenumber}`. `TimeDomainCube` overrides it with `{Off, Peak, Time, Offset}`.
  - `HyperspectralCube.normalize_spec -> NormalizeSpec`:
    - `mode` is the parsed `NormalizeMode` attribute when it is present, parses and is supported; otherwise `Off`.
    - `reference` is `float(NormalizeWavenumber)` when that attribute is present, otherwise `None`. It is returned whatever the mode, to match SDK `GetNormalizeSpec`.
  - `GeneratedImage.normalize_spec -> NormalizeSpec | None`: the image's own setting.
    - `NormalizeMode` absent: `None`.
    - present but unparseable: mode `Off`.
    - `reference` comes only from the image's own `NormalizeWavenumber`.
  - `HyperspectralCube.resolve_normalize_spec(image: GeneratedImage | None = None) -> NormalizeSpec`:
    - When the image has its own spec, return the image's mode if this cube supports it (otherwise `Off`), paired with the image's own reference.
    - Otherwise return `self.normalize_spec`.

    Like the SDK, it does not check that `image` is a child of this cube.
